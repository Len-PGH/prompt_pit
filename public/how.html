How it works

The Prompt Pit

An esports-style control room for a live vibe-coding championship. One container drives every screen in the room and lets the whole audience vote from their phones — by web, text, or a phone call answered by an AI agent — all into one live tally.

01The surfaces

Every screen is a page served by the same server and kept in lock-step over WebSockets. Change something in the booth and the projector updates instantly.

🖥️

Stage /stage

The big screen: matchup, countdown, scores, surprise modifiers, QR codes, champion celebration.

🎛️

Operator /operator

Booth control — bracket, timers, judging, voting, show-flow phases. Key-gated with scoped access.

📱

Vote /vote

What the audience opens from the on-screen QR. One tap for Station A or B.

📝

Register /register

Contestant portal: format, what to bring, challenge picker, starter kits, sign-up.

📊

Stats /stats

Live leaderboard: bracket results, votes by channel per contestant, modifier log.

02Three ways to vote, one tally

The audience doesn't need an app. Whichever way a vote comes in, it lands in the same per-match count and is de-duplicated per device or phone number.

03One container, one URL

Everything ships in a single Docker container and is exposed through one Cloudflare tunnel — so the web app, the phone agent, and SMS all live on the same public URL.

☎️ Caller / 💬 Texter / 🌐 Phone browser → Cloudflare tunnel (one URL) → Node + Socket.IO app :3000 → /agent, /sms → Python SignalWire agent :8100

The Node app serves the web surfaces and reverse-proxies /agent and /sms to the Python SignalWire Agents-SDK service. The phone agent and SMS webhook post votes back to the app's internal bridge, so voice/SMS votes and web votes share one source of truth.

04Running a match

  1. Register & draw — contestants sign up at /register; the operator draws 8 into the bracket.
  2. Introduce — Stage shows the matchup and the active challenge.
  3. Compete — the operator starts the countdown; contestants build live.
  4. Judge — judges tick each prompt's completion checklist + set the weighted rubric (→ /100) from the operator panel.
  5. Vote — voting opens; the audience votes by web, SMS, or phone.
  6. Declare — one button combines judges' scores + audience votes and crowns the round winner, advancing the bracket.
  7. Champion — win the final and the Stage erupts.

05Built to be safe to run live

Secrets stay in a git-ignored .env and are never baked into the image. Audience pages never receive personal data (emails stay server-side, sent only to authenticated operators). Operator keys are scoped and revocable, and the app runs as a non-root user with security headers and a strict CSP.
